# Save inventory and order authority

NiaSave owns Save inventory, prices, reservations, orders, cancellation, pickup receipts and handover events. Central supplies current approved member identity/fulfilment and staff site scope. Central displays the same NiaSave records through signed operations; there is no inventory Sheet read, copied Central order book, or automatic migration from old books.

## Storage and rollback

`nia_runtime_state` key `niasave-save-v1` is schema version 1. It starts absent; reads return an empty unavailable source (`sourceReady:false`, version 0), with no seeded SKUs/sites/members. Only an authenticated, scoped and validated first inventory publication initializes an empty book. One versioned compare-and-swap saves all inventory/order/event/idempotency changes; losing contenders reload and re-evaluate. Missing/unavailable durable storage never acknowledges a write. First publication uses the existing additive runtime-store schema helper if needed. Deployment/build does not initialize stock or migrate data.

`niasave-save-auth-v1` separately holds signed gateway replay nonces. Reading through the signed gateway can create/update this authentication-only key. Legacy `operation-polo`, Living and historical Central tables remain untouched by this implementation. Session authentication continues to use its existing store.

Set `NIASAVE_SAVE_ENABLED=1` only in the reviewed environment. Default is off. It additionally requires COMMERCE_ENABLED=1, DUMMY_DATA=0, durable Postgres configuration and signed HTTPS Central connection; COMMERCE_PREVIEW=1 and NIA_SHOWCASE=1 cannot enable it. A real isolated Vercel Preview is supported. The browser receives `capabilities.saveReservations` from its current uncached member catalogue; no static build toggle can bypass server enforcement. Live/Earn, legacy stock, online payments and transfers remain paused. Disabling the flag stops new Save writes without deleting the new book. Preserve/export both dedicated keys before any deliberate data rollback; do not restore old software expecting legacy stock to contain these orders.

## Native desk and signed operations

Native `/api/commerce/staff/save/snapshot` and `/orders` are GET. POST `/inventory-preview`, `/inventory-publish`, `/complete` use the existing active staff session and same-origin protection. Existing admins or exact configured `NIASAVE_SAVE_OPERATOR_EMAILS` entries may access this dedicated desk; the allowlist changes no global role/legacy page access. Every native request additionally fetches signed `save.staffScope` using `staff:<verified work email>`, and requires Central's current admin/operator role and verified site scope.

The existing signed `/api/central/commerce` gateway accepts line `save`, actions `snapshot`, `orders`, `inventory-preview`, `inventory-publish`, `complete`. `_siteScope` is supplied only by the signing Central server, as `{siteCode,name,theatre}[]`; it is stripped from business commands before idempotency comparison. Admins may write; operators read scoped stock/orders; readers receive aggregate counts. The native dedicated operator grant permits that scoped desk's writes without changing global roles. No staff response exposes a member pickup code or member identity.

Inventory preview body: `{rows}`. Each of at most 100 rows contains `siteCode,sku,productId,name,pack,pricePaise,onHand,countedAt,priceVerifiedAt,active,expectedRevision`, with optional `evidence`. Price is positive integer paise, physical on-hand a nonnegative integer **including held units**, booleans are actual booleans, timestamps are dated verification/counts. Zero is accepted; missing, unknown, stale/future, duplicate or out-of-scope values fail the whole request. Pack must be confirmed. `expectedRevision` is zero for a new SKU/site and the current revision otherwise. Existing product IDs cannot silently map to another SKU. Optional evidence and actor/time/full submitted rows remain in the publication event.

Preview returns normalized rows, previewHash, rowCount, asOf and stockMeaning; it never writes. Publish sends identical rows/hash and a stable 16–100 character idempotency key. Exact replay returns the prior receipt before checking the advanced revision. Changed payload with the same key fails. Current revision, site scope and physical count >= active holds are checked again inside CAS. No partial import occurs. Native and signed bodies are bounded to 256 KiB.

Member catalogue, quote, reserve, history, retry-status and cancel read/write only this book after a current `save.locations` eligibility/fulfilment read. Guests receive no invented local/TEST stock. Only pickup is enabled. Quotes are signed and bind the member, site, service revision, SKU, price, quantity and expiry. Reserve rechecks stock/window/current mapping and commits order+hold+event+replay together. Price/count verification freshness remains required. Expired holds release availability without background writes. A new independent random pickup code is visible only to the member, not derived from the public order ID.

Completion requires `{orderId,expectedRevision,pickupCode,amountPaise,paymentEvidence,handoverEvidence,idempotencyKey}`. It checks the current scoped unexpired reservation and exact total/code, records pickup payment and handover, deducts on-hand once, advances stock/order revisions, and stores the receipt in the same CAS write. It does not charge a card/UPI rail, verify bank settlement or send money. Member payment view is `{status:'received',method:'at_pickup',amountPaise,receivedAt,bankSettlementVerified:false}`; staff-only evidence does not leak to member history. Cancellation releases holds without deducting stock. No blind historical conversion occurs.

## Board summary

Only the exact signed actor `{id:'central-save-summary',role:'service'}` may call line `save`, action `save-summary`; this role is rejected for any staff/read/write operation. Body `{month:'YYYY-MM'}` is optional, defaulting to current India month. Replay protection is durable.

Response: `{owner:'niasave',schemaVersion:1,sourceReady,version,asOf,month,stockRows,completedRows,counts}`. Stock rows contain siteCode, sku, onHand, reserved, available, active, countedAt. Completed rows group actual pickup receipt month/site/SKU into quantity and revenuePaise; costPaise and savingsPaise are null because no approved cost source exists. No member/order IDs, pickup codes, phone numbers or evidence are included. Central maps sites to its verified theatre metadata and preserves unavailable/unknown state when sourceReady is false; it must not treat absence as verified zero.

## Verification boundaries

Offline tests cover mocked durable reload/CAS contention, last-unit oversell, failed save rollback, quote tampering, cross-member/site denial, physical-count bounds, publication replay, cancellation, receipt/handover and nonce/service-role separation. These are not real provider or browser UAT evidence. Live release still requires exact integration review, configured Central staff scope, approved inventory source inputs, isolated database retry/concurrency proof and authenticated desktop/mobile flow verification. Original records and real stock must never be fabricated for release checks.
